Describe people with one `User` shape (`{ pid, name, color, isMe }`) across the API. Presence views, cursor presence views, and the presence objects passed to `shouldRenderCursor` / `getCursorStyle` now include `user`; `onProximityEntered` receives `user` as a fourth argument; and React adds `useMe()` plus `me` on `usePresence()`. The cursor callbacks `onProximityLeft` and `onCustomCursorRender` now document their first argument as `pid` (the value is unchanged). `playerIdentity` on views, `presence.getMyIdentity()`, `usePresence().myIdentity`, `usePlayerIdentity()`, and `getMyPlayerIdentity()` keep working but are deprecated. `user` is now a reserved presence channel name, so `setMyPresence("user", …)` throws.

Adds one presence API built on `User`. Every list of people's presence is `{ user, presence }[]` named `everyone` (including you). Page presence lives on `playhtml.page`: `setPresence({ key: value })` merges keys (`null` clears one), `getEveryone(key?)`, and `onPresenceChange(callback)` / `onPresenceChange(key, cb)` / `onPresenceChange(select, cb)`, which fire only when the watched part changes. Presence rooms expose the same methods. Elements take a `presence` default and receive `myPresence`, `everyone`, and `setPresence`; handles add `getMyPresence()`, `getEveryone()`, `setPresence()`, and `onPresenceChange(select?, cb)`, which works before the element binds. Cursors are readable from `playhtml.users.cursors` (`getAll()`, `onChange()`). React adds `usePagePresence()`, `useCursors()`, and `myPresence` / `everyone` / `setPresence` render props. `playhtml.presence`, `room.presence`, `usePresence`, `useCursorPresences`, and the element `live` / `users` / `setLive` names keep working as deprecated aliases (development mode logs a one-time notice for the older `awareness` names and `playhtml.presence`). Nothing about stored or synced data changes.
