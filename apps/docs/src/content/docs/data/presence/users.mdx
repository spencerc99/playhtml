Every person in [`playhtml.people`](/docs/data/presence/) has a `pid`, a `name`, and a `color`. Unlike [presence](/docs/data/presence/), these are saved: they follow a person from visit to visit, and they work whether or not cursors are enabled.

- `pid` is a stable id for this person in this browser. Use it as a React `key` or to match someone across features.
- `name` is whatever they've set, or `undefined`.
- `color` is always set. playhtml picks one the first time someone visits.
- `isMe` is `true` for you.

## `people.me`

You. Reading `me` gives you the same fields as everyone else; setting `me.name` or `me.color` saves the change and shows it to everyone.

```js
playhtml.people.me.name;   // "Alice"
playhtml.people.me.color;  // "#3b82f6"
playhtml.people.me.pid;    // a stable id

// Save and show a new name
playhtml.people.me.name = "Bob";

// Save and show a new color (also updates your cursor, if cursors are enabled)
playhtml.people.me.color = "#ff0000";
```

Your presence is on `me` too, at `me.presence`.

## A live roster

`playhtml.people.onChange(callback)` calls back now and whenever someone joins, leaves, or changes their name, color, or presence. It returns an unsubscribe function.

<Tabs syncKey="framework">
  <TabItem label="Vanilla HTML">
```js
function renderRoster(everyone) {
  const list = document.querySelector("#roster");
  list.innerHTML = "";
  for (const person of everyone) {
    const item = document.createElement("li");
    item.textContent = person.name ?? "anonymous";
    item.style.color = person.color;
    list.appendChild(item);
  }
}

const unsubscribe = playhtml.people.onChange(renderRoster);
```
  </TabItem>
  <TabItem label="React">
```tsx
import { usePeople } from "@playhtml/react";

function Roster() {
  const { everyone } = usePeople();

  return (
    <ul>
      {everyone.map((person) => (
        <li key={person.pid} style={{ color: person.color }}>
          {person.name ?? "anonymous"}
        </li>
      ))}
    </ul>
  );
}
```

## A name and color picker

<Tabs syncKey="framework">
  <TabItem label="Vanilla HTML">
```html
<input id="my-name" placeholder="your name" />
<input id="my-color" type="color" />

<script type="module">
  import { playhtml } from "https://unpkg.com/playhtml@latest";

  await playhtml.init();
  const nameInput = document.getElementById("my-name");
  const colorInput = document.getElementById("my-color");
  nameInput.value = playhtml.people.me.name ?? "";
  colorInput.value = playhtml.people.me.color;

  nameInput.addEventListener("change", () => (playhtml.people.me.name = nameInput.value));
  colorInput.addEventListener("input", () => (playhtml.people.me.color = colorInput.value));
</script>
```
  </TabItem>
  <TabItem label="React">
```tsx
import { playhtml, usePeople } from "@playhtml/react";

function Profile() {
  const { me } = usePeople();
  return (
    <>
      <input
        value={me.name ?? ""}
        onChange={(e) => (playhtml.people.me.name = e.target.value)}
      />
      <input
        type="color"
        value={me.color}
        onChange={(e) => (playhtml.people.me.color = e.target.value)}
      />
    </>
  );
}
```

Before playhtml has connected, `usePeople().me` has an empty `pid` and `color`.

## Earlier names

`playhtml.users` (`me`, `getAll()`, `onChange()`) and the `User` type are the earlier form of this API. They keep working: `users.getAll()` returns the same people as `people.everyone`, without `presence`. In React, `useUsers()` and `usePlayerIdentity()` keep working too; use `usePeople()` in new code. `window.cursors.color` and `window.cursors.name` are also still aliases for `people.me.color` and `people.me.name` (see [the legacy cursor API](/docs/data/presence/cursors/#legacy-global-api-windowcursors)).

See the [people and presence reference](/docs/reference/presence/) for full signatures.
