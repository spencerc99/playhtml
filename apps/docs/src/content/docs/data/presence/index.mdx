Presence is per-person state that only exists while someone is on the page: "Ana is typing", "Sam is hovering the lamp", "Jo's cursor is here". When a person leaves, their presence is gone, and someone who arrives later never sees it.

playhtml splits presence into three parts:

- **Who is here:** [`playhtml.users`](/docs/data/presence/users/) gives each person's name and color.
- **Where they are:** [cursors](/docs/data/presence/cursors/) (`playhtml.users.cursors`).
- **What they are doing:** presence values you set, on the page (`playhtml.page`) or on one element.

When you want something to stay after a refresh, use [persistent data](/docs/data/data-essentials/). For one-off moments that don't change any state (a burst of confetti), use [events](/docs/data/events/).

For the full API surface (`User`, `PresenceEntry`, `playhtml.page`, cursor types), see the [Presence & identity reference](/docs/reference/presence/).

## Page presence

Each person has one presence object for the page. `setPresence` merges the keys you pass into yours, so separate features can each own a key without overwriting each other. Everyone reads it back as a list of `{ user, presence }`, including you.

<Tabs syncKey="framework">
  <TabItem label="Vanilla HTML">
```js
// Set a key on your presence (other keys are kept)
playhtml.page.setPresence({ status: { text: "focused", icon: "target" } });

// Read everyone (including you; user.isMe marks you)
for (const { user, presence } of playhtml.page.getEveryone()) {
  user.name;        // "Ana"
  user.color;       // "#3b82f6"
  presence.status;  // { text, icon } or undefined
}

// Watch one key: fires now, then only when someone's status changes
const unsubscribe = playhtml.page.onPresenceChange("status", (everyone) => {
  renderStatusList(everyone); // each entry's presence is just their status
});
```
  </TabItem>
  <TabItem label="React">
```tsx
import { usePagePresence } from "@playhtml/react";

function StatusList() {
  // Watches one key; setPresence writes just that key.
  const { myPresence, everyone, setPresence } = usePagePresence<{ text: string }>("status");

  return (
    <>
      <button onClick={() => setPresence({ text: "focused" })}>focus</button>
      {everyone.map(({ user, presence }) => (
        <span key={user.pid} style={{ color: user.color }}>
          {presence?.text ?? "…"}
        </span>
      ))}
    </>
  );
}
```

The component re-renders only when someone's `status` changes.
  </TabItem>
</Tabs>

### Watching exactly what you need

Subscriptions take what to watch first, and fire only when that part changes:

```js
playhtml.page.onPresenceChange(callback);                        // the whole presence object
playhtml.page.onPresenceChange("status", callback);              // one key
playhtml.page.onPresenceChange((p) => p.status?.text, callback); // a selection
```

`usePagePresence()` takes the same three forms. With a selector, return a string, number, or small object so changes elsewhere in someone's presence don't trigger your callback.

### Setting and clearing

```js
playhtml.page.setPresence({ status: "typing" });  // set a key
playhtml.page.setPresence({ status: null });      // remove a key
```

Top-level keys merge, but values inside a key replace: `setPresence({ status: { icon: "wave" } })` replaces the whole `status`. If two separate features on your page both use presence, give their keys distinct names (`chatTyping`, `lobbyReady`) so they don't collide.

Presence is for **state changes**, not per-frame streams. Each person's page presence writes are rate limited (about 20 per second), and extra writes are dropped. For pointer position, use [cursors](/docs/data/presence/cursors/). For scroll position or similar, throttle your writes.

## Element presence

Use element presence when the signal belongs to one playhtml element, like "who has joined this widget" or "which choice is this reader previewing here". Give the element a starting `presence`, change yours with `setPresence`, and render everyone from `everyone`.

<Tabs syncKey="framework">
  <TabItem label="Vanilla HTML">
```html
<button id="ready-count">0 ready</button>

<script type="module">
  import { playhtml } from "playhtml";

  playhtml.register("ready-count", {
    presence: { ready: false },
    onClick: (_event, { myPresence, setPresence }) => {
      setPresence({ ready: !myPresence.ready });
    },
    update: ({ element, everyone }) => {
      const ready = everyone.filter(({ presence }) => presence.ready).length;
      element.textContent = `${ready} of ${everyone.length} ready`;
    },
  });

  playhtml.init();
</script>
```
  </TabItem>
  <TabItem label="React">
```tsx
<CanPlayElement id="ready-count" defaultData={{}} presence={{ ready: false }}>
  {({ myPresence, everyone, setPresence }) => {
    const ready = everyone.filter(({ presence }) => presence.ready).length;
    return (
      <button onClick={() => setPresence({ ready: !myPresence.ready })}>
        {ready} of {everyone.length} ready
      </button>
    );
  }}
</CanPlayElement>
```
  </TabItem>
</Tabs>

On an element, `everyone` means everyone who has that element on screen, each starting at the element's `presence` value. `setPresence` on an element replaces your value (the page merges, because many features share it; an element owns its value).

You can also read and watch an element's presence from elsewhere on the page through its handle:

```js
const lamp = playhtml.getHandle("lamp");
lamp.getEveryone();                              // [{ user, presence }]
lamp.onPresenceChange((p) => p.hovering, (everyone) => {
  badge.textContent = everyone.filter(({ presence }) => presence).length;
});
```

Tabs in the same browser share one identity and appear as one person. To test with two people, open the second copy in an incognito window or another browser profile.

## Isolated presence rooms

Page presence covers everyone on the page. When you want presence **scoped to something other than the page** (a lobby, a document, a game table that several pages share), create a presence room. A room has the same presence API as `playhtml.page`.

<Tabs syncKey="framework">
  <TabItem label="Vanilla HTML">
```js
const room = playhtml.createPresenceRoom("lobby-42");

room.setPresence({ status: { text: "ready" } });
const unsubscribe = room.onPresenceChange("status", renderLobby);

// When you're done (e.g. the user leaves the lobby), tear it down:
room.destroy();
```

Always call `destroy()` when the room is no longer needed; it closes the connection and clears your presence for everyone else.
  </TabItem>
  <TabItem label="React">
```tsx
import { usePresenceRoom } from "@playhtml/react";

function Lobby() {
  const room = usePresenceRoom("lobby-42");
  if (!room) return null; // null until joined
  return (
    <button onClick={() => room.setPresence({ ready: true })}>
      {room.getEveryone().length} in the lobby
    </button>
  );
}
```

[`usePresenceRoom(name)`](/docs/reference/react-api/#usepresenceroom) joins the room and tears it down for you on unmount.
  </TabItem>
</Tabs>

## Migrating from `playhtml.presence`

Earlier versions used a channel-based `playhtml.presence` object and element `live` values. They still work, but new code should use the API above.

| Before | Now |
| --- | --- |
| `playhtml.presence.setMyPresence("status", v)` | `playhtml.page.setPresence({ status: v })` |
| `playhtml.presence.getPresences()` | `playhtml.page.getEveryone()` |
| `playhtml.presence.onPresenceChange("status", cb)` | `playhtml.page.onPresenceChange("status", cb)` |
| `playhtml.presence.onPresenceChange("cursor", cb)` | `playhtml.users.cursors.onChange(cb)` |
| `usePresence("status")` | `usePagePresence("status")` |
| `room.presence.setMyPresence(...)` | `room.setPresence({ ... })` |
| element `live`, `setLive`, `users` | `presence`, `setPresence`, `everyone` (your own value is `myPresence`) |

## When to use data instead

Presence is for the live sense of other people on the page. If you find yourself reaching for `localStorage` or a refresh-survivor, you want data, not presence.

Not sure which primitive fits? The full decision table, covering element data, page data, presence, cursors, and events, is on [data essentials](/docs/data/data-essentials/#when-to-use-which-primitive).
