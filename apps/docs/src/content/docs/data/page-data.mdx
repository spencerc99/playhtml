Page data is a persistent data channel keyed by a name, with no DOM element required. Good for counters, vote tallies, link trackers, anything page-shaped instead of element-shaped.

## Try it

The background color below is one page data channel named `"page-color"`. The swatches in the top and bottom corners are separate elements, and both write that same channel. No element owns the color; the page does. It's saved, so it's still there when you reload.

## Create a channel

<Tabs syncKey="framework">
  <TabItem label="Vanilla HTML">
`playhtml.createPageData(name, default)` returns a channel handle:

```js
const counter = playhtml.createPageData("my-counter", { count: 0 });
counter.setData((draft) => { draft.count += 1; });
counter.onUpdate((data) => { /* re-render */ });
```
  </TabItem>
  <TabItem label="React">
The [`usePageData`](/docs/reference/react-api/#usepagedata) hook wraps `createPageData` with `useState`-style ergonomics and manages the channel's lifecycle for you:

```tsx
import { usePageData } from "@playhtml/react";

function VisitCounter() {
  const [data, setData] = usePageData("visits", { count: 0 });
  return (
    <button onClick={() => setData((draft) => { draft.count += 1; })}>
      {data.count} visits
    </button>
  );
}
```
  </TabItem>
</Tabs>

Channels can also hold a primitive value. Pass the next value directly or return
the next value from a functional update:

```js
const viewCount = playhtml.createPageData("viewCount", 0);
viewCount.setData((value) => value + 1);
```

For object and array channels, function updates are mutators: edit the draft in
place. For primitive channels, the function's return value becomes the next
stored value. Nullable channels can be cleared with `setData(null)` or an updater
that returns `null`:

```ts
const selection = playhtml.createPageData<{ name: string } | null>("selection", null);
selection.setData({ name: "Alice" });
selection.setData(null);
```

Other return values from object and array mutators are ignored. Pass an object
or array directly to replace it.

The vanilla channel handle exposes four methods (`usePageData` wraps these for you):

- **`getData()`**: read the current value synchronously.
- **`setData(value | updater)`**: write. Pass a replacement value, mutate an object/array draft in place, or return the next primitive value from an updater; see [data best practices](/docs/advanced/data-best-practices/#updating-data-mutator-vs-replacement).
- **`onUpdate(cb)`**: subscribe to changes. Returns an unsubscribe function.
- **`destroy()`**: detach the channel and its observers. Call this when the channel is no longer needed (e.g. on teardown) to avoid leaking the subscription.

`onUpdate` batches synchronous writes into one callback with the final value.

When you should reach for `createPageData` vs. element data, presence, or events: see the [decision table in core concepts](/docs/concepts/#when-to-use-which-primitive).

## Navigation

Page data is room-scoped, like element data. On a single-page app, when navigation changes the room the channel resets to the new room: it reads its default until re-seeded. A channel handle you hold across the navigation stays usable (it keeps writing and notifying). Navigation that doesn't change the room leaves the data untouched. See [Navigation & SPAs](/docs/advanced/navigation/).
